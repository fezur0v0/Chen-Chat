# 对话 API

`context.js` 负责收集上下文，`transport.js` 负责协议适配，`controller.js` 管理请求、停止和保存，`view.js` / `style.css` 提供输入区的状态与操作。入口为 `src/app.js` 的 compose 提交事件。

## 实际发送的内容

- 当前选定模型、角色名称和角色设定，用户称呼，自动附加的已实现 `<live>` 格式说明。
- 当前会话最近最多 40 条消息、约 60000 字符的历史正文。不混入其他会话、旧场景存档、手动记忆或日记。
- 最近最多 6 张可用用户图片，转换为接口的图片内容格式。是否支持图片取决于模型；失败时不自动换模型或剥离附件重发。
- 已有语音转写、引用内容与文件元信息。没有转写的音频、普通文件内容不会发送，也不会声称模型已读到。
- 默认预设中启用的文本提示词，按列表和基础聊天深度排列；支持 chatHistory 标记、{{char}} / {{user}}。角色设定固定在请求系统信息中，不依赖其他预设标记。尚未实现世界书触发、其他宏和高级标记、正则、向量、工具或自动记忆。
- 预设的 openai_max_tokens 限定为 1–8192，未设置时为 4096。其他生成参数暂不执行；stream 固定为 false，接收完整回复再展示。

## 协议与凭据

OpenAI 兼容和 DeepSeek 使用 `/chat/completions`；Anthropic 使用 `/messages`；Gemini 使用 `/models/{model}:generateContent`。保留用户基础地址的路径前缀。系统信息和图片按接口转换，不发送其他厂商的专有参数。Anthropic / Gemini 的系统条目合并到顶层；相邻同身份消息合并。

使用现有 provider.js 凭据存储，只读取当前厂商与基础地址对应的密钥。密钥放在请求头，不写入聊天状态、错误提示或备份。浏览器直连需要服务端允许 CORS；本实现不增加代理服务器。模型有独立计费和能力限制，检测到模型不代表生成权限已验证。

## 生命周期

1. 先保存用户消息，成功后发出请求。每个会话最多一个等待中的请求，按钮与 Enter 都防止重复提交。可在等待时继续写草稿。
2. 回复保存到发起请求的会话；切换页面不会把回复放到当前其他会话，也不会刷新正在编辑的设置表单。编辑、回滚、删除历史或恢复备份时，过期回复不会写回。
3. 停止和 180 秒超时会中断本地等待；无法保证服务端停止计算或撤销计费。失败不会自动再次请求，用户可以手动重试，原用户消息不会再插入一次。
4. 回复已收到但本机保存失败时，暂存于本次页面内存，提供复制和“重试保存”；该操作不重新请求模型。关闭页面会失去尚未保存的回复，请先复制或保存。
5. 仅保存可显示正文及模型 ID，不存储 reasoning_content / thinking 等原始推理。助手正文上限 60000 字符；普通用户消息仍为 12000。备份恢复保留助手正文的完整上限；现有编辑入口仍仅支持用户消息。
6. 应用内的聊天样式预览已移除。验证使用独立浏览器环境、假的凭据与拦截响应，不调用付费接口。

相关验证见 `tests/chat-api.test.js`。实际模型输出仍可能不遵循格式，前端沿用原有的安全转义与容错渲染，不执行模型生成的脚本。
